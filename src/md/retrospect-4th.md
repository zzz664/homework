# 네 번째 회고

## 🚀 1. 이번 주의 '성장' 포인트

### "Flexbox밖에 모르는 우물 안 개구리에서 한계를 넘어 Grid라는 새로운 세계를 맛보다."

이전까지는 `flex`를 중첩하여 레이아웃을 잡는 방식에 익숙했습니다. 복잡한 구조를 만들 때마다 불필요한 `wrapper` 태그가 늘어나고 코드가 길어지는 것에 불편함을 느꼈지만, 익숙함에 안주해왔습니다.

- **변화:** 이번 주 Grid의 핵심 원리를 학습하며, 여러 겹의 wrapping 없이도 단 몇 줄의 속성으로 레이아웃을 제어하는 효율성을 경험했습니다.
- **성장:** 이제는 특정 레이아웃을 마주했을 때 단순히 '동작하는 방법'이 아니라, **"Flex와 Grid 중 어떤 것이 더 선언적이고 간결한가?"** 를 고민하는 관점을 갖게 되었습니다.

### "감이 아닌 설계에 기반한 마크업"

전공자로서 구현은 가능했지만, 항상 '스타일링 후에 남는 불필요한 CSS 코드'와 '수정하기 두려운 복잡한 구조'가 고민이었습니다.

- **변화:** 이번 실습과 과제를 통해 원자, 분자, 유기체 단위로 나아가는 단계별 접근 방식을 연습했습니다.
- **성장:** 마크업을 시작하기 전, 구조를 먼저 분석하고 **"어떻게 하면 가장 효율적인 스타일링 경로를 만들 수 있을까?"** 를 먼저 설계하는 습관을 들였습니다. 덕분에 이전보다 훨씬 정갈하고 유지보수가 용이한 코드를 작성할 수 있게 되었습니다.

### ✅ 성취감

- 주먹구구식 마크업에서 벗어나, 체계적인 구조 위에서 스타일을 입히는 프로세스를 정립했습니다.
- 불필요한 CSS 속성을 덜어내고, 코드의 의도가 명확히 드러나는 레이아웃을 구현했을 때의 쾌감을 느꼈습니다.

### 🧗‍♀️ 도전 과제

- **Subgrid에 대한 이해:** Grid의 강력함은 체감했지만, `subgrid`를 활용해 부모 Grid와 자식 요소 간의 레이아웃을 동기화하는 부분은 아직 직관적으로 와닿지 않습니다. 다음 주에는 실전 예제에 `subgrid`를 적용해 보며 내 것으로 만드는 시간이 필요합니다.

## 🎯 2. 앞으로의 다짐

> "돌아가는 코드를 만드는 개발자는 많지만, **누구나 읽기 쉽고 수정하기 편한 코드를 만드는 개발자** 는 드물다."

이번 주에 느낀 '설계의 중요성'을 잊지 않고, 남은 부트캠프 기간 동안에도 단순히 과제를 끝내는 것에 급급하기보다 **최선의 구조** 를 고민하는 연습을 지속하겠습니다.
